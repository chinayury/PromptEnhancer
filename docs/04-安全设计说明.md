# 安全设计说明 · 提示词工坊 PromptForge v0.1.9

> **文档版本**：V1.0 ｜ **审查日期**：2026-10-12（首轮）· 2026-10-28（第二轮）· 2026-11-08（第三轮）· 2026-11-10（第四轮）
> **审查方法**：全量源码逐条核查（白盒）+ 隔离实例动态渗透（96 项用例）
> **结论**：**未发现可利用的高危漏洞**；四轮累计完成多项加固，其余复核为已有防护或设计取舍并记录。

---

## 一、安全架构总览

提示词工坊的安全架构围绕六大风险面设计：**认证与会话、路由权限、注入与路径、SSRF 与外呼、信息泄露、依赖供应链**。核心原则：

- **本地优先**：所有数据存于本地 SQLite，默认不出本机。
- **最小依赖**：运行时第三方依赖极小（Web 版仅 Flask + Waitress，桌面版仅 customtkinter），供应链风险低。
- **纵深防御**：每层独立设防，单一防线被突破仍有后续屏障。
- **绝不猜测**：指令构造纯本地，无网络调用面。

## 二、认证与会话

| 机制 | 实现 | 评估 |
|---|---|---|
| 口令哈希 | 标准库 `pbkdf2_hmac(sha256)`，240,000 轮 + 16B 随机盐（OWASP 2023 推荐档），`hmac.compare_digest` 恒时比较 | 通过；零第三方依赖 |
| 管理员三重认证 | 用户名 + 密码 + 平台口令（`WEB_ACCESS_PASSWORD`）；口令错与密码错同文案防管理员账号枚举；平台口令不落库不进日志 | 通过 |
| 登录限流 | 账号维度：连续失败 5 次锁定 15 分钟（DB 持久化，**原子 UPDATE** 消竞态）；IP 维度：失败 20 次/10 分钟（内存态） | 通过；阻断字典喷洒 |
| 登录计时匀势 | 对不存在的用户也执行一次同等成本 PBKDF2（导入期一次性预算哑哈希），封堵账号枚举计时侧信道（实测耗时差 0.035s） | 通过 |
| 会话 | Flask 签名 Cookie，30 天；密钥持久化于 `data/.web_secret`（0600）；登录/注册前 `session.clear()`（防固定）；每请求与账号库对账（停用/软删立即踢线、角色变更即时同步） | 通过 |
| Cookie 属性 | 显式 `HttpOnly` + `SameSite=Lax`；`WEB_COOKIE_SECURE=1` 可开启 `Secure` | 通过 |
| 强制改密 | 管理员下发口令 `must_change=1`，未改密前业务与管理接口全拦（逃生通道：改密/登出/查本人） | 通过 |
| 防枚举 | 不存在/密码错统一文案；锁定/停用属运维状态如实告知（行业通行取舍） | 通过 |

## 四、输入校验

### 4.1 SQL 注入防护

全部语句参数化（`?` 占位）；唯一字符串拼接进 SQL 的是 `VACUUM INTO` 的文件名，已做单引号转义且目标路径由服务端生成（时间戳 + 递增序号）。FTS 分支对关键字做双引号短语转义，LIKE 分支对 `%`/`_`/`\` 做 ESCAPE 转义。

### 4.2 路径穿越防护（重点）

用户名进入 `data/users/<name>/` 路径。四层防线：

1. 建号正则 `^[A-Za-z0-9_一-龥]{2,32}$`（无 `.` `/` `\` 空格）。
2. 管理端 URL 参数先经 DB 存在性校验。
3. Flask 默认路由转换器不匹配 `/`。
4. `workspace_dir` 内同款正则二次校验（防直接篡改 pf_users 表的纵深防御），非法名在 `global_stats`/`workspace_stats` 中计 broken/零值不中断。

### 4.3 XSS 防护

前端所有用户内容渲染均经 `esc()`（&<>"' 全转义）或 `textContent`；属性上下文双引号 + `&quot;`；`onclick` 内联仅注入经 `jsq()` 转义且建号正则保证不含引号的用户名。服务端无 JSON 拼 HTML（全 `jsonify`）。**未发现注入路径**。

### 4.4 CSRF 防护

写接口全部要求 `Content-Type: application/json`（跨站表单无法伪造该头，`get_json(silent=True)` 对表单编码返回 None）；GET 无副作用；DELETE 方法表单发不出。Cookie `SameSite=Lax`（双保险）。

### 4.5 模板注入防护（jinja2 边界，重点）

`render_variables` 仅开放简单变量替换：`{%`/`{#` 语句与注释语法整体拒绝；`{{...}}` 内容必须整体匹配 `[A-Za-z0-9_]+`（`a.b`、`a["b"]`、`7*7`、`user.__class__` 等表达式一律拒绝）；StrictUndefined；变量值只做替换不求值。**`{{ 表达式 }}` 注入路径不存在**。

### 4.6 命令注入防护

无任何 shell 调用（`os.system` / `subprocess` / `eval` / `exec`）；forge 中的命令识别仅为正则匹配，结果作提示词锚点回显，**绝不执行**。

### 4.7 日志敏感信息

API Key 不写日志（保存配置只记 provider/model；引擎与异常路径均不含 Key）；平台口令仅登录瞬间比对。

## 五、凭据管理

| 项 | 策略 |
|---|---|
| API Key 存储 | 本地 SQLite `app_config` 表（明文）；支持 `PROMPTFORGE_API_KEY` 环境变量覆盖，规避明文落库 |
| API Key 回显 | 本人自见（与桌面版一致，用于表单回填）；管理端只回 `api_key_set` 掩码；环境变量注入时前端置灰不显示 |
| API Key 日志 | 任何写日志处不得包含 `api_key` 等敏感字段（代码注释与日志模块双重约束） |
| 缓存键 | `make_key = sha256(model+messages+规范化params)`，**绝不存储 API Key** |
| 平台口令 | `WEB_ACCESS_PASSWORD` 不落库、不进日志，仅登录瞬间比对 |
| 会话密钥 | 持久化于 `data/.web_secret`（0600），不随代码分发 |

## 六、SSRF 与外呼面

- 增强请求的 `base_url` 由用户在连接配置中自填（厂商预设 + 自定义）——**产品核心能力**（自带 Key / 自建或局域网模型端点，如 vLLM/Ollama 是主要用例），不做私网地址封禁。
- 服务器自身不主动外呼任何地址；指令构造纯本地。
- **风险取舍与缓解**：本服务应部署于内网或受信网络；公网暴露必须前置 HTTPS 反向代理并加访问控制。容器内进程仅能访问其网络可达范围，data 卷不含系统敏感路径。

## 七、安全响应头与降级策略

### 7.1 安全响应头

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- `Content-Security-Policy`：`default-src 'self'`、`connect-src 'self'`（强制增强调用走服务端转发）、`img-src 'self'`（站点图标可引用）。前端为内联脚本/样式单页，`script-src`/`style-src` 需 `'unsafe-inline'`（已记录为设计取舍）。

### 7.2 降级策略

| 场景 | 降级行为 |
|---|---|
| SQLite 不支持 FTS5 | 历史检索自动回退 LIKE 全表扫描（`%`/`_` 转义） |
| SQLite 不支持 trigram | trigram 需 ≥3 字符，更短关键字自动退 LIKE |
| 缓存异常 | 任何缓存异常只记 warning 并忽略，**绝不影响增强结果** |
| 版本链指针不一致 | `repair_consistency()` 幂等自愈，异常只记日志不阻断启动；带 rollback 审计的指针刻意豁免 |
| 用量统计异常 | `record_usage` 全异常兜底（告警不抛），统计永不打断业务 |
| 日志文件不可写 | 不阻断主流程，仅控制台输出 |
| 模型响应缺失 usage | 按 0 记，不报错 |
| 模型响应畸形 | `_chat_request` 逐层 isinstance 校验，结构异常按空内容处理 |

## 十、剩余风险登记（接受/缓解）

| 风险 | 等级 | 处置 |
|---|---|---|
| SSRF（用户自填 base_url） | 中 | 设计取舍（内网自建端点是主用例）；缓解：内网部署/反代+HTTPS |
| CSP 需 `unsafe-inline`（内联脚本/样式单页） | 中 | 已记录；后续可改非静态散列/nonce |
| 批量增强长时间占用线程（≤200×90s） | 低 | 上限+前端确认；后续可做任务队列 |
| 注册/登录限流为内存态，重启清零 | 低 | 已知限制；重启窗口极短 |
| CSV 导出无公式注入防护 | 低 | 自用场景；提示用户勿将导出文件直接交 Excel 公式执行 |
| 已登录态改密接口试旧密码无独立限流 | 低 | 攻击前提是已持有效会话；账号级锁定在登录侧仍有效 |
| `.web_secret` 与数据卷权限依赖宿主 OS | 低 | chmod 0600（Windows 平台差异）；部署建议磁盘访问控制 |
| 注册接口重名提示的枚举面 | 低 | IP 限流 + 开关可关；内网工具可接受 |
| 评估裁判输出依赖模型遵循 JSON 指令 | 低 | 已多级容错（剥围栏/钳位/逐字段校验），解析失败显式报错不落库 |
| 版本链内容长期膨胀 | 低 | content ≤20 万字符/条且有去重门，未做配额上限；可后续加每记录版本数上限 |

## 十一、总体结论

- **高风险漏洞**：无。
- **中风险**：SSRF（用户自填 base_url，设计取舍）与 CSP 需 `unsafe-inline`（内联单页固有取舍）——均已记录缓解措施。
- **低风险**：日志/异常/路径规范已在代码中落实；第三方依赖面极小且无已知高危 CVE。
- **可部署性**：六类安全面（SQL 注入、命令注入、路径遍历、信息泄露、越权、逻辑绕过）审计结论均为「安全 / 不适用」，96 项动态渗透用例全部通过。

**结论：提示词工坊 v0.1.0 满足可部署要求，未发现可利用漏洞，可在受控内网环境中投入正常使用。** 公网部署需前置 HTTPS 反向代理并加访问控制。
