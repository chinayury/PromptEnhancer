# 环境部署教程 · 提示词工坊 PromptForge v0.1.3

> **文档版本**：V1.1 ｜ **对应代码版本**：v0.1.3 ｜ **版权归属**：智维ITMSKY
> **适用对象**：运维、部署与二次分发人员
> **编写依据**：`Dockerfile`、`docker-compose.yml`、`deploy.sh`、`deploy.bat`、`build_exe.bat`、`requirements-web.txt`、`requirements.txt`、`pyproject.toml`、`src/promptforge/webapp.py`、`src/promptforge/__main__.py` 实际代码。

提示词工坊是一款本地优先的提示词工作台，一个仓库、两种形态。本文档记录两种形态的环境要求、部署方式、数据持久化、升级备份与故障排查。

---

## 一、环境要求

### 1.1 Web 多用户版（Docker 部署，主交付形态）

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Linux / Windows / macOS（Docker 可用即可） |
| 容器运行时 | Docker 20+ + Docker Compose v2 |
| 基础镜像 | `python:3.11-slim`（Dockerfile 内置） |
| Web 依赖 | flask>=3.1.3、waitress>=3.0.2、werkzeug>=3.1.3、jinja2>=3.1.6（由 `requirements-web.txt` 锁定安全下界） |
| 端口 | 宿主机 6085 → 容器 8000 |

### 1.2 桌面单机版

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows（主要目标平台；GUI 依赖 customtkinter + tkinter） |
| Python 版本 | 运行 GUI 需**带 tkinter 的 Python**；打包构建须用**系统 Python 3.14** |
| 核心依赖 | `customtkinter>=5.2.0`（GUI 必需；同时隐式要求 tkinter） |
| 可选依赖 | `pyinstaller`（仅打包发布时需要） |

### tkinter 注意事项（重点）

- **系统 Python 3.14** 自带 tkinter 8.6，可正常启动 GUI 并完成打包构建。
- **托管 Python 3.13** 不含 tkinter，仅适合运行 `cli` 无头模式，**不能**用于启动 GUI，也**不能**用于打包。
- 若运行 GUI 报 `No module named 'tkinter'` / `No module named 'customtkinter'`，说明当前 Python 缺少相应组件，需切换 Python 版本或安装依赖。

## 三、Web 版部署（Docker，推荐生产形态）

### 3.1 一键部署

**Linux / macOS（`deploy.sh`）**

```bash
./deploy.sh                 # 首次: 生成 .env(随机口令) → 构建 → 后台启动
docker compose logs -f promptforge    # 跟踪日志
docker compose down                   # 停止
```

`deploy.sh` 的真实行为：`cd` 到脚本所在目录 → 若无 `.env` 则 `cp .env.example .env` → 若 `.env` 中口令仍是 `change-me` 占位值，则用 openssl（或 `/dev/urandom`）生成 **18 位字母数字强随机口令**替换 `WEB_ACCESS_PASSWORD` 与 `WEB_ADMIN_PASSWORD` 并回显 → `mkdir -p data` → `docker compose up -d --build`。

**Windows（`deploy.bat`）**

```bat
deploy.bat
```

注意：`deploy.bat` **不自动生成随机口令**——若 `.env` 不存在，它只复制 `.env.example` 并提示你先编辑填入两个口令，然后退出（退出码 1），需要填好后重跑。

### 3.2 手动部署

```bash
cp .env.example .env        # 编辑填入 WEB_ACCESS_PASSWORD / WEB_ADMIN_PASSWORD
docker compose up -d --build
```

### 3.3 compose 关键事实

| 项 | 值 |
|---|---|
| 服务名 / 容器名 | `promptforge` / `promptforge` |
| 镜像标签 | `promptforge:v0.1.3` |
| 端口映射 | `6085:8000`（改左半边即可换宿主机端口） |
| 数据卷 | `./data:/app/data` |
| 重启策略 | `restart: always` |
| 环境变量 | `TZ=Asia/Shanghai`、`WEB_ACCESS_PASSWORD`、`WEB_ADMIN_PASSWORD`（均从同目录 `.env` 读取） |
| 构建参数 | `PIP_INDEX_URL` 默认传清华镜像（海外服务器改回 `https://pypi.org/simple`） |

### 3.4 Dockerfile 关键事实

- 基础镜像 `python:3.11-slim`；`ENV TZ=Asia/Shanghai`、`LANG=C.UTF-8`、`PYTHONDONTWRITEBYTECODE=1`、`PYTHONUNBUFFERED=1`、`PYTHONPATH=/app/src`。
- 依赖层：`pip install --no-cache-dir -r requirements-web.txt`（**只装 Web 依赖**，桌面版 `customtkinter` 不进镜像）。
- 复制进镜像的内容：`COPY src ./src`；`RUN mkdir -p /app/data`。
- `EXPOSE 8000`、`VOLUME ["/app/data"]`、`CMD ["python", "-m", "promptforge.webapp"]`。

### 3.5 本地裸跑（不依赖 Docker）

```bash
pip install -r requirements-web.txt
python -m promptforge.webapp              # 默认监听 0.0.0.0:8000
# 可选：改监听地址/端口
HOST=127.0.0.1 PORT=9000 python -m promptforge.webapp
```

启动行为（源自 `webapp.py` 的 `main()`）：

- 初始化全局库（`promptforge.db`）、账号表 `pf_users`、全局用量表 `api_usage`。
- 首次启动创建内置管理员 `admin`，口令来源见 `WEB_ADMIN_PASSWORD`。
- 未设置 `WEB_ACCESS_PASSWORD` 时打印告警：管理员登录不校验平台口令，生产环境务必配置。
- 使用 Waitress 提供服务的线程数固定为 **8**。
- 浏览器访问 `http://127.0.0.1:8000`。

健康检查：`curl http://127.0.0.1:8000/healthz`，返回 `{"ok": true, "version": "<版本号>"}`（与 `pyproject.toml` 声明一致）。

### 3.6 常用运维命令

```bash
docker compose logs -f promptforge      # 跟踪日志
docker compose down                     # 停止
docker compose up -d --build            # 改配置/改代码后重建
curl http://127.0.0.1:6085/healthz      # 健康检查
```

日志文件同时落在 `./data/promptforge.log`。

## 四、桌面版部署

### 4.1 源码运行

```bash
pip install -r requirements.txt
python -m promptforge                    # 桌面 GUI
python -m promptforge cli --help         # 命令行模式
python -m promptforge cli --text "写个登录页面"
python -m promptforge cli --file prompts.txt --out enhanced.csv
```

CLI 复用与 GUI 完全相同的增强引擎和本地数据库连接，行为一致。可用环境变量 `PROMPTFORGE_API_KEY` 覆盖密钥，避免明文落库。

### 4.2 五槽指令构造器 CLI

```bash
python -m forge --help
python -m forge --file <设计文档.md> --outline              # 第一步：只看目录锚点
python -m forge --file <设计文档.md> --pick 3,6.6 --period 一期 \
    --code src/auth.py --task "实现用户登录接口" --decision "采用 JWT 方案"
python -m forge --file <设计文档.md> --pick 3 --out instruction.txt --no-gate
```

### 4.3 打包发布（build_exe.bat）

打包目标：生成可双击运行的单文件 `dist/PromptForge.exe`（PyInstaller `--onefile`）。

```bat
build_exe.bat
```

**流程要点**：

1. 检查系统 Python 3.14 是否存在（脚本中路径为 `C:\Python314\python.exe`）。
2. 在项目内创建独立构建虚拟环境 `.build_venv`。
3. 在虚拟环境中安装 `customtkinter` 与 `pyinstaller`。
4. 调用 PyInstaller 构建单文件 exe（耗时约 2–5 分钟）。入口为 `src/promptforge/__main__.py`，`--paths src` 指定包搜索路径。
5. 产物输出到 `dist/PromptForge.exe`。

**必须使用系统 Python 3.14**：托管 Python 3.13 不含 tkinter，无法完成 GUI 构建。

**构建前清空 safe-delete 环境变量**：

```bat
set CODEBUDDY_SESSION_ID=
set CLAUDE_SESSION_ID=
```

若不清除，会话中的 safe-delete 拦截 shim 会导致 PyInstaller 中断，构建失败。

**资源收集要点**：

- `--collect-data customtkinter`：customtkinter 的主题 JSON 属于数据文件，不收集则 exe 启动即崩溃。
- `--add-data "src/promptforge/config/providers.json;promptforge/config"`：厂商预设数据文件必须随包携带。
- `--collect-submodules promptforge` / `--collect-submodules forge`：确保业务包与 forge 子包的所有子模块都被收集。

### 4.4 exe 数据持久化

- 数据层通过 `sys.executable` 判断运行态：`frozen` 模式下取 exe 真实路径所在目录。
- 数据目录固定为 **exe 同目录下的 `data/`**：数据库文件 `data/promptforge.db`、备份目录 `data/backups/`、日志 `promptforge.log`。
- **升级时替换 exe 时务必保留 `data/` 目录**，仅覆盖 `PromptForge.exe` 即可。误删 `data/` 会导致历史记录与连接配置丢失。

## 五、环境变量说明

> 事实来源：`.env.example` + `webapp.py` + `engine.py` + `users.py` + `logging_setup.py` + `Dockerfile`。

| 变量 | 用途 | 默认值 | 安全约束 | .env.example 收录 |
|---|---|---|---|---|
| `WEB_ACCESS_PASSWORD` | **平台口令**：管理员登录的第三因子 | 空（= 管理员不校验口令，仅限内网测试） | **强烈建议设置**；不落库、不进日志 | ✅ |
| `WEB_ADMIN_PASSWORD` | 内置管理员 `admin` 的**初始密码**（仅首次启动建号时使用） | 空（= 系统随机生成并打印一次） | 登录后立即修改 | ✅ |
| `PROMPTFORGE_API_KEY` | 注入模型 API Key，**优先于所有用户在界面保存的值** | 未设置 | 设为该项可避免密钥落库 | ✅（注释项） |
| `WEB_COOKIE_SECURE` | 会话 Cookie 的 `Secure` 属性开关 | `0`（关闭） | HTTPS/反代部署建议设 `1` | ✅（注释项） |
| `HOST` | Web 服务监听地址 | `0.0.0.0` | 容器内一般不改 | ❌ |
| `PORT` | Web 服务监听端口 | `8000` | 容器内一般不改；宿主机端口在 compose `ports` 左半边改 | ❌ |
| `PROMPTFORGE_CACHE` | LLM 响应缓存总开关 | `1`（开启） | 关闭时**既不读也不写**缓存；缓存键不含 API Key | ❌ |
| `PROMPTFORGE_LOG_FILE` | 日志文件路径 | 未设置（默认 `data/promptforge.log`） | 日志不含 API Key | ❌ |
| `TZ` | 容器时区 | `Asia/Shanghai`（Dockerfile `ENV`） | — | ❌ |
| `PIP_INDEX_URL` | 构建期 pip 源 | `https://pypi.org/simple`；compose 传清华镜像 | 仅影响镜像构建 | ❌ |

> 使用方式：`cp .env.example .env` 后填写；`docker compose` 会自动读取同目录 `.env`。

## 六、升级与备份

### 6.1 数据零迁移

- v0.1.0 各轮迭代均**无表结构变更**（`llm_cache` 表随缓存首次使用自动建立，`favorite`/`current_version_id` 列为惰性补加）。
- `./data` 目录原样沿用，无需任何数据迁移脚本。
- 回滚：代码还原 + compose `image:` 改回旧标签即可；新增数据对旧版只读无害。

### 6.2 数据库原子备份（VACUUM INTO）

数据层提供 `backup_database()`，通过 SQLite `VACUUM INTO` 生成一致、独立的数据库副本：

- 备份文件命名：`data/backups/promptforge_YYYYMMDD.db`（同日多次清空递增序号，不覆盖旧备份）。
- 同时写出 `.sha256` 校验和文件。
- 自动仅保留最近 30 份备份（`BACKUP_RETAIN=30`）。
- 该备份在「清空业务数据」前自动触发（清空仅删 `enhance_records`，连接配置 `app_config` 始终保留）。

手动触发（在源码环境下）：

```bash
python -c "from promptforge.data import database as db; print(db.backup_database())"
```

### 6.3 项目整体备份

```bash
# 打包整个项目目录（含源码、配置、data/ 数据库与日志）
powershell -Command "Compress-Archive -Path 'D:\1.软件开发\正在开发\PromptEnhancer-提示词工坊' -DestinationPath 'promptforge_backup.zip'"
```

### 6.4 回滚

- 从项目 zip 恢复：解压对应版本 zip 覆盖回原目录（保留或恢复 `data/`）。
- 从数据库备份恢复：用 `data/backups/` 下的 `.db` 副本替换 `data/promptforge.db`，并以同名 `.sha256` 校验一致后再启用。
- 回滚后建议重新启动验证 `init_db()` 能正常打开数据表。

## 七、故障排查表

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 访问 6085 无响应 | 容器未运行 / 端口映射错误 | `docker compose ps` 确认容器在跑；`docker compose logs -f promptforge` 看日志；本地裸跑确认端口是 8000 |
| 首次登录不知道口令 | `.env` 未配置口令 | `WEB_ADMIN_PASSWORD` 见 `.env` 或启动日志；未设则系统随机生成并在日志打印一次；管理员另需 `WEB_ACCESS_PASSWORD` |
| 启动报 `no such table: ...` | 数据库表未建立 | 确认入口已调用 `init_db()`；源码直接运行会在入口自动建表 |
| exe 双击后一闪即退 / 启动即崩 | customtkinter 主题资源未入包 | 确认打包时加了 `--collect-data customtkinter`；缺失主题 JSON 会导致启动崩溃，重新按第 4 节构建 |
| 运行报 `No module named 'tkinter'` | 当前 Python 不含 tkinter | 切换为系统 Python 3.14（自带 tkinter 8.6）；托管 Python 3.13 不可启动 GUI |
| 运行报 `缺少 customtkinter 库` | 未安装 GUI 依赖 | 执行 `pip install -r requirements.txt`，或改用 `python -m promptforge cli` 无头模式 |
| 打包时 PyInstaller 中途中断 | 会话 safe-delete shim 拦截 | 构建前清空 `CODEBUDDY_SESSION_ID` 与 `CLAUDE_SESSION_ID`（见 4.3） |
| 运行时找不到厂商配置 / 预设 | `providers.json` 未入包 | 确认打包含 `--add-data "src/promptforge/config/providers.json;promptforge/config"` |
| GUI 启动但历史记录为空 | 误删或挪动了 `data/` | 检查 exe 同目录 `data/promptforge.db`；用第 6 节备份或项目 zip 恢复 |
| 升级后配置/历史丢失 | 替换 exe 时删除了 `data/` | 升级仅覆盖 `PromptForge.exe`，保留 `data/`；丢失后用备份回滚 |
| CLI 报「请至少提供 --text 或 --file 之一」 | 缺少输入参数 | 补 `--text` 或 `--file` 后重试 |
| 批量导出 CSV 中文乱码 | 打开方式不当 | 文件以 `utf-8-sig` 写出（含 BOM），用 Excel 直接打开即可正确识别 |
| 升级后提示登录限流 | 每 IP 20 次/10 分钟为 v0.1.0 新增 | 等待 10 分钟（或重启容器清零内存计数）；正常使用不会触发 |
| 清空历史后想找回 | 清空前已自动原子备份 | 备份文件名在状态栏可见，从 `data/backups/` 恢复 |
| `import promptforge` 失败 | src 布局未安装 / PYTHONPATH 未设置 | `pip install -e .` 或设 `PYTHONPATH=src`；Docker 镜像内已设 `PYTHONPATH=/app/src` |
