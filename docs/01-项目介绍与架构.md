## 一、项目概述

提示词工坊 PromptForge 是一款**本地优先**的提示词工作台，一个仓库、两种形态：

1. **Web 多用户版**（主交付形态，Docker 部署）：Flask + Waitress，每个账号独立工作区，浏览器直接访问。含单条/批量增强、Prompt Lint 静态体检、双版对比配对判定、历史档案与全文检索、Token 用量与成本统计、提示词版本链与回滚、五槽指令构造、LLM 响应缓存、完整管理后台；界面为「钴蓝工坊 · Cobalt Forge」全浅色视觉体系。
2. **桌面单机版**（`python -m promptforge`）：customtkinter 单窗口，提示词增强 + 指令构造双模块，数据结构与 Web 版完全同构。

两大核心模块：

1. **提示词增强**：把一句原始提示词，借助任意**通用兼容**文本生成接口，改写为更清晰、更专业、更可执行的版本。
2. **指令构造器（五槽）**：把一份技术设计文档编译成「文档定位 + 本期切片 + 反向边界 + 可执行验收 + 歧义停工」的结构化指令，纯本地、零远程调用、省 token；支持 `{{变量名}}` 模板变量。

所有数据（连接配置、增强历史、清空审计、用量明细、LLM 响应缓存）均存于本地 SQLite，**默认不上云**。

### 1.1 用户画像与角色

| 角色 | 关注点 | 典型场景 | 对应能力 |
|---|---|---|---|
| 管理者 | 本地化、数据不出本机、审计可追 | 团队内推广，要求密钥不落库明文、清空可备份可审计 | 本地 SQLite、`PROMPTFORGE_API_KEY` 覆盖、原子备份+审计、管理后台 |
| 开发者 | 增强质量、批量效率、失败可定位、指令可复现 | 打磨提示词 / 把设计文档切片成可执行指令 | 单条/批量增强、四风格、历史复用、五槽指令、版本链、Lint、A/B 对比 |

### 1.2 项目范围

**本期包含**：提示词增强（单条/批量/历史/统计/检索/收藏/导出）、指令构造（五槽/切片/变量）、Prompt Lint 体检、A/B 双版对比、版本链与回滚、评估裁判、Token 用量与缓存、多用户账号体系与管理后台、命令行双形态。

**本期不包含**（列为后续规划）：云端同步 / 多人协同编辑、单条历史删除、UI 状态记忆、模板外置多语言、`serve` 子命令、A/B 完整统计显著性检验、批量增强服务端可取消。

## 二、核心设计原则

- **分层解耦**：业务（`promptforge.core`）、数据（`promptforge.data`）、配置（`promptforge.config`）、表现（`gui` / `cli` / `webapp`）、工具（`utils`）各司其职。表现层只负责交互与渲染，不内嵌业务判断；引擎层只依赖标准库，可被桌面界面、命令行、Web、测试独立复用。
- **本地优先**：所有连接配置、增强历史、清空审计、用量明细、LLM 响应缓存均存于本地 SQLite，默认不出本机；指令构造模块（`forge`）纯本地解析与装配，不发起任何远端调用。
- **最小依赖**：增强引擎仅用标准库（`urllib` / `json` / `socket`），不引入网络或渲染第三方库；界面层才依赖 `customtkinter`，且通过包初始化延迟导入以支持无桌面环境；Web 版仅依赖 Flask + Waitress。
- **可测性**：可测的业务状态机（如 `forge.gui_model.InstructionController`）与 tkinter 完全分离，使绝大多数 GUI 逻辑可在无桌面环境下以单测覆盖；数据库层提供 `set_base_dir` 钩子便于测试重定向数据目录。
- **绝不猜测**：指令构造槽位撑不起来即标 `❓待填` 并进「歧义停工」清单，绝不替用户猜测填充。

## 三、关键技术选型

| 层 | 选型 |
|---|---|
| Web 服务 | Python 3.11 + Flask 3.1+ + Waitress 3.0+（`threads=8`） |
| 桌面 GUI | Python + customtkinter（仅桌面版一个第三方 GUI 依赖） |
| 增强引擎 | **纯标准库** `urllib` / `json` / `socket`，调用任意 OpenAI 兼容 `/chat/completions` |
| 持久化 | SQLite（标准库 `sqlite3`）+ FTS5 + trigram 分词全文检索（支持中文子串匹配，需 sqlite ≥ 3.34；不支持时自动回退 LIKE 全表扫描） |
| 口令哈希 | 标准库 `pbkdf2_hmac(sha256)`，240,000 轮 + 16B 随机盐 |
| 前端 | 原生 HTML/CSS/JS 单页（无构建、无框架），内联线性 SVG 图标 |
| 容器 | `python:3.11-slim`，`docker compose` 编排，数据卷 `./data` |

### 4.1 目录结构

```

├── promptforge/              核心包：提示词增强

│   ├── __main__.py           桌面 GUI / CLI 入口（python -m promptforge）
│   ├── webapp.py             Web 版入口（全部 API 路由、环境变量、启动逻辑）
│   ├── cli.py                命令行模式（无界面，多场景适配）
│   ├── core/                 业务层：增强引擎、模板、Lint 体检
│   │   ├── engine.py         HTTP 调用、结构化异常、重试、低质量判定、缓存开关
│   │   ├── templates.py      SYSTEM/USER 模板、风格化约束、选项白名单
│   │   └── lint.py           Prompt Lint 静态体检规则与九维维度
│   ├── data/                 数据层：SQLite 持久化、备份、审计、统计
│   │   ├── database.py       建表/迁移、配置读写、记录写入、原子备份、统计
│   │   ├── users.py          账号体系：PBKDF2、锁定、限流、工作区隔离
│   │   ├── usage.py          Token 用量与成本统计
│   │   ├── versions.py       提示词版本链、diff、评估裁判、repair_consistency
│   │   └── llm_cache.py      LLM 响应缓存
│   ├── config/               配置层
│   │   ├── providers.py      厂商预设加载（单一真源 + 兜底）
│   │   └── providers.json    厂商端点（热更新）
│   ├── gui/                  表现层·桌面（customtkinter）
│   │   ├── app.py            主窗口、各功能页、交互逻辑
│   │   └── widgets.py        统一按钮组件
│   ├── utils/                工具层
│   │   └── logging_setup.py  统一日志（控制台+文件、脱敏）
│   └── web/                  前端资源
│       ├── index.html        主界面（单条/批量/档案/铸造/管理台）
│       ├── login.html        登录/注册页
│       └── favicon.svg       钴蓝工坊品牌标
│
└── forge/                    指令构造引擎：纯本地文档编译
    ├── __init__.py
    ├── __main__.py           命令行入口（python -m forge）
    ├── parser.py             文档结构解析：标题树 / 命令 / 期次 / 待确认
    ├── assembler.py          五槽装配：任务/输入/范围/禁止/验收 + 停工清单 + 收益报告
    ├── templates.py          五槽骨架常量、默认禁止项、自检清单、出口门禁
    ├── gui_model.py          InstructionController：纯逻辑状态机（无 tkinter 依赖）
    ├── gui.py                ForgePanel（可嵌入主窗口）/ ForgeApp（独立运行）
    └── cli.py                指令构造命令行
```

### 4.2 依赖方向（单向，无环）

```
gui / cli / webapp  ──►  core  ──►  utils
     │  │              │
     └──► data ────────┘
     └──► config
     └──► forge（指令构造，纯本地，被 gui/webapp 引用其控制器）
```

- **表现层**（`gui` / `cli` / `webapp`）只负责渲染与交互，所有业务委托给 `core` / `data` / `config` / `forge`。
- **业务层** `core` 不 import 任何 GUI/存储模块，仅依赖标准库与 `utils`，可独立测试。
- **数据层** `data` 不感知 UI，仅提供函数式接口。
- **配置层** `config` 提供厂商预设，文件为单一真源。
- `forge` 是独立的指令构造引擎，**不依赖** `promptforge`；`webapp.py` 与 `promptforge/gui/app.py` 引用 `forge` 的 `assembler` 与 `gui_model.InstructionController`。

### 4.3 双形态入口

| 形态 | 入口 | 说明 |
|---|---|---|
| Web 多用户版 | `python -m promptforge.webapp` | Flask + Waitress，每用户独立工作区库（`data/users/<username>/promptforge.db`），线程局部绑定隔离 |
| 桌面单机版 | `python -m promptforge` | customtkinter 单窗口，数据落在 `data/promptforge.db`（全局单库） |
| 命令行 | `python -m promptforge cli` / `python -m forge` | 无界面，复用与 GUI/Web 完全相同的引擎与数据层 |

> `promptforge/__init__.py` 不贪婪导入 `gui` / `cli`，仅在入口按需导入，因此无桌面（服务器/CI）环境可直接 `import promptforge` 并运行命令行模式，无需安装 `customtkinter`。

## 五、模块职责说明

### 5.1 `promptforge.core`（业务层 · 增强引擎）

- **职责**：调用任意兼容 `/chat/completions` 的远端文本生成接口，将用户输入改写为更清晰、更专业的提示词；抛出结构化异常；对空结果做有限次重试；对疑似复述原文做低质量标记；配置校验；LLM 响应缓存开关。
- **关键常量**：`DEFAULT_TIMEOUT = 90`、`MAX_RETRIES = 2`、`TEMP_WHITELIST = {"0.3","0.5","0.7","0.9","1.0"}`、`MAXTOKEN_WHITELIST = {"512","1024","2048","4096"}`、`MAX_OUTPUT_CHARS = 800`（软上限，仅告警不截断）。
- **关键函数**：`engine.enhance(cfg, text, timeout, max_retries)`、`engine.validate_config(cfg)`、`engine.is_low_quality(text, output)`、`engine.raw_completion(cfg, system, user, ...)`。
- **结构化异常体系**：`EnhanceError`（基类，带 `code` + `hint`）派生 `AuthError` / `RateLimitError` / `TimeoutErrorEx` / `NetworkError` / `EmptyResponseError` / `ConfigError`。7 个稳定 code：`AUTH_FAILED` / `RATE_LIMITED` / `TIMEOUT` / `BAD_RESPONSE` / `EMPTY_RESULT` / `MODEL_NOT_CONFIGURED` / `UPSTREAM_ERROR`。
- **`core.templates`**：`SYSTEM_TEMPLATE` / `USER_TEMPLATE` / `STYLE_GUIDANCE` / `STYLE_LABEL_TO_KEY` / `TEMP_OPTIONS` / `MAXTOKEN_OPTIONS`。
- **`core.lint`**：Prompt Lint 静态体检（纯本地规则，零模型调用），九维维度汇总，安全规则组。

### 5.2 `promptforge.data`（数据层 · SQLite）

- **职责**：初始化数据表并对旧列做兼容迁移；配置与业务数据分表；原子备份（`VACUUM INTO` + 校验和 + 留存清理）；统计聚合；多用户工作区隔离；版本链管理；LLM 响应缓存。
- **关键函数**：`init_db()`、`load_config()`、`save_config(cfg)`、`append_record(...)`、`load_records(limit)`、`backup_database()`、`clear_records()`、`log_clear(...)`、`get_clear_logs(limit)`、`get_stats()`、`set_base_dir(path)`、`get_db_path()`。
- **`users.py`**：账号体系——`pf_users` 表（PBKDF2-SHA256 240k 轮 + 16B 盐、失败锁定、口令历史、软删除、防枚举）、每用户独立工作区、线程局部绑定、`workspace_dir` 路径纵深防御。
- **`usage.py`**：`api_usage` 明细表，记录每次增强的 token 用量与成本折算。
- **`versions.py`**：`prompt_versions` 版本链表 + `version_audit` 审计表 + `current_version_id` 指针列；`repair_consistency()` 幂等自愈（rollback 审计豁免）；difflib 结构化 diff。
- **`llm_cache.py`**：`llm_cache` 表，`make_key = sha256(model+messages+规范化params)`，TTL 支持，`_cursor()` 幂等建表。
- **路径与常量**：`BASE_DIR` 开发态取 `<项目根>/data`，PyInstaller frozen 态回落到 exe 同目录 `data/`；`BACKUP_RETAIN = 30`；`DISPLAY_LIMIT = 100`。

### 5.3 `promptforge.config`（配置层）

- **职责**：加载厂商预设（`providers.json` 为单一真源）；文件缺失/损坏时回退内置 `DEFAULT_PROVIDERS`。
- **关键函数**：`load_providers()` 返回 `{厂商名: {base_url, model, note}}`。

### 5.4 `promptforge.gui`（表现层 · 桌面）

- **职责**：基于 `customtkinter` 的桌面交互与渲染；业务与持久化全部委托给 `core` / `data` / `config`。
- **关键类**：`PromptForgeApp`（主窗口，构建侧边栏、主内容区、状态栏、四页）；`widgets.pill(...)`。
- **页面**：`single`（单条增强）、`batch`（批量增强）、`history`（历史档案）、`forge`（指令构造，嵌入 `forge.gui.ForgePanel`）。

### 5.5 `promptforge.cli`（表现层 · 命令行）

- **职责**：无界面模式，复用与 GUI 完全相同的引擎与数据库连接。
- **关键函数**：`cli.run(argv)` —— 基于 `argparse` 解析参数，支持单条文本（`--text`）与文件批处理（`--file` + `--out` CSV）；密钥可由环境变量 `PROMPTFORGE_API_KEY` 覆盖。

### 5.6 `promptforge.utils`（工具层）

- **职责**：统一日志规范。
- **关键函数**：`configure_logging(level)`（幂等，控制台 + 文件双出口）、`get_logger(name)`、`set_log_file(path)`。约束：日志内容不得包含密钥等敏感字段。

### 5.7 `forge`（指令构造引擎 · 纯本地）

- **`forge.parser`**：`parse(text, doc_path)` 解析设计文档为结构化字典（标题、代码块、命令、待确认项、分期、依赖），全部带原文行号。**红线**：只抽取归类，不生成文档中不存在的内容。
- **`forge.assembler`**：`assemble(doc, picks, task, code_files, decisions, period, add_exit_gate=True)` 填充五槽骨架并产出报告与歧义停工清单；`approx_tokens(text)`。
- **`forge.templates`**：五槽骨架 / 默认禁止项 / 自检清单 / 出口门禁等静态常量；`PLACEHOLDER = "❓待填"`。
- **`forge.gui_model`**：`InstructionController`（纯逻辑，不 import tkinter），串起 解析 → 选节 → 装配。
- **`forge.gui`**：`ForgePanel`（可嵌入主窗口）、`ForgeApp`（独立运行入口）。
- **`forge.cli`**：`main(argv)` —— 文档/粘贴文本 → 五槽提示词，支持 `--outline` / `--pick` / `--task` / `--code` / `--decision` / `--period` / `--out` / `--no-gate`。

### 5.8 `promptforge.webapp`（Web 版入口）

- **职责**：Flask 应用全部 API 路由、环境变量解析、启动逻辑、安全响应头、会话管理、工作区隔离。
- **关键机制**：每用户独立工作区库、管理员三重认证、登录双维限流、安全响应头、会话 Cookie、Waitress `threads=8`。

### 5.9 `promptforge/web/`（前端）

- **`index.html`**：主界面单页，含吸顶横向导航台、五大页面、钴蓝工坊视觉体系、内联线性 SVG 图标。
- **`login.html`**：登录/注册双栏门厅页。
- **`favicon.svg`**：钴蓝六边形品牌标。
- **技术**：原生 HTML/CSS/JS，无构建、无框架，内联脚本/样式。前端所有用户内容渲染均经 `esc()` 转义或 `textContent`。

## 六、数据模型

数据库文件：开发态 `data/promptforge.db`（Web 版每用户独立工作区库 `data/users/<username>/promptforge.db`；打包态落到 exe 同目录 `data/`）。连接时启用 **WAL**（`PRAGMA journal_mode=WAL`）与 `PRAGMA foreign_keys=ON`，仅使用标准库 `sqlite3`，所有写操作采用 `?` 占位符参数化。

### 6.1 `app_config`（连接配置，单行）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PRIMARY KEY CHECK (id = 1) | 固定单行 |
| `provider` | TEXT | 厂商名 |
| `api_key` | TEXT | 密钥（界面以 `*` 掩码，落库不进日志） |
| `base_url` | TEXT | 接口地址 |
| `model` | TEXT | 目标服务名 |
| `updated_at` | TEXT | 最近更新时间（ISO） |

> 兼容迁移：`temperature` / `max_tokens` / `style` 三列在 `_migrate_columns` 中按需 `ALTER TABLE ADD COLUMN`。

### 6.2 `enhance_records`（增强业务记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 自增主键 |
| `created_at` / `date` | TEXT | 完整时间戳 / 日期 |
| `provider` / `model` / `base_url` | TEXT | 调用上下文快照 |
| `input_text` / `output_text` | TEXT | 原始 / 增强结果 |
| `input_chars` / `output_chars` | INTEGER | 字数 |
| `status` | TEXT | `success` / `failed` |
| `error_msg` | TEXT | 失败原因（截断至 500 字） |
| `duration_ms` | INTEGER | 耗时 |
| `source` | TEXT | `single` / `batch` / `migrated` |
| `prompt_tokens` / `completion_tokens` | INTEGER | 用量 |
| `request_id` | TEXT | 远端返回标识 |
| `quality` | TEXT | 空或 `low_quality` |
| `style` | TEXT | 增强风格 |
| `favorite` | INTEGER NOT NULL DEFAULT 0 | 收藏标记（惰性补列） |
| `current_version_id` | INTEGER | 版本链当前指针（惰性补列） |

**索引**：`idx_rec_created`(created_at)、`idx_rec_date`(date)、`idx_rec_provider`(provider)、`idx_rec_status`(status)。

### 6.3 `clear_log`（清空审计）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 自增主键 |
| `cleared_at` | TEXT | 清空时间 |
| `backup_path` | TEXT | 清空前备份文件路径 |
| `records_removed` | INTEGER | 删除条数 |
| `reason` | TEXT | 触发原因 |

### 6.4 `prompt_versions`（提示词版本链）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 自增主键 |
| `record_id` | INTEGER | 所属历史记录（FK → enhance_records.id ON DELETE CASCADE） |
| `version_no` | INTEGER | 版本号（UNIQUE(record_id, version_no) 防并发撞号） |

### 6.8 备份机制（原子快照）

- `backup_database()`：先 `os.makedirs(BACKUP_DIR)`，以 `YYYYMMDD` 命名；同日多次清空递增序号避免覆盖。
- 使用 **`VACUUM INTO '<safe_target>'`** 生成一致性、独立的数据库副本（对单引号做转义）。
- 写 `.sha256` 校验和；随后 `_prune_backups()` 仅保留最近 `BACKUP_RETAIN = 30` 份。
- 失败时抛 `BackupError`，清空流程会因此中止。

## 七、配置管理

- **单一真源**：`src/promptforge/config/providers.json`。`load_providers()` 优先读取该文件，返回 `{厂商名: {base_url, model, note}}`；其结构与内存常量 `DEFAULT_PROVIDERS` 保持一致。

## 八、接口 / 函数契约

### 8.1 `engine.enhance`


## 九、关键实现取舍

1. **结构化异常映射**：把所有传输层错误翻译成业务语义异常，状态码分流让 GUI/CLI/Web 能精确提示。
2. **空结果重试隔离**：仅 `EmptyResponseError` 重试，其余异常直接上抛。
3. **低质量判定**：用 `difflib` 相似度而非纯相等，捕捉「换汤不换药」的复述。
4. **WAL + 外键**：提升并发读写并启用外键约束。
5. **原子备份**：`VACUUM INTO` 在写事务进行中也能产出一致副本。
6. **迁移隔离**：仅在默认 data 目录才迁移旧数据，配合 `set_base_dir()` 测试钩子，单元测试用独立目录时绝不会误搬生产库。
7. **章节编号优先级**：标题自带编号优先，否则按层级推算，顶层文档标题不可选。
8. **反向边界去重**：归一化空白消除正则分组前导空格造成的重复。
9. **歧义停工**：缺槽位一律 ❓ 标记进 `unresolved`，工具绝不替用户猜测。
10. **控制器与界面分离**：`gui_model.InstructionController` 纯逻辑、可单测，使 90% 的 GUI 风险可在无桌面环境回归。
