# 功能使用说明 · 提示词工坊 PromptForge v0.1.0

> **文档版本**：V1.0 ｜ **日期**：2026-11-13 ｜ **对应代码版本**：v0.1.0
> **适用对象**：PromptForge Web 多用户版（Flask + Waitress，Docker 部署，默认 `http://服务器IP:6085`）与桌面单机版
> **编写依据**：v0.1.0 最终真实代码。本文不描述代码中不存在的能力。

## 一、认识工坊

提示词工坊 PromptForge 是一款**本地优先**的提示词工作台，一个仓库、两种形态：

| 形态 | 入口 | 说明 |
|---|---|---|
| **Web 多用户版**（主交付形态） | `python -m promptforge.webapp` 或 Docker | Flask + Waitress，每个账号一套独立工作区，浏览器直接访问 |
| **桌面单机版** | `python -m promptforge` | customtkinter 单窗口，提示词增强 + 指令构造双模块 |

两大核心模块：

1. **提示词增强**：把一句原始提示词，通过任意**通用兼容 OpenAI `/chat/completions`** 的接口，改写为更清晰、更专业、可执行的版本。
2. **指令构造器（五槽）**：把一份技术设计文档编译成「任务 + 输入切片 + 范围 + 反向边界 + 验收」的结构化指令，**纯本地、零远程调用、不消耗 token**；支持 `{{变量名}}` 模板变量。

所有数据均存于本地 SQLite，**默认不上云**。

### 1.1 视觉体系：「钴蓝工坊 · Cobalt Forge」

全站浅色单主题，无暗色主题。登录页为「门厅 + 登录台」双栏；主界面为吸顶横向导航台 + 编号水印页面头版；全部图标为内联线性 SVG。

```bash
./deploy.sh                          # 一键: 生成 .env(随机口令) → 构建 → 启动
```

```bash
pip install -r requirements-web.txt && python -m promptforge.webapp

```

```bash
pip install -r requirements.txt       # 仅 customtkinter
python -m promptforge                 # 桌面 GUI
python -m promptforge cli --text "写一个登录页"
python -m forge --file <设计文档.md> --outline
```

## 三、Web 版五大页面

### 3.0 通用：连接参数（铸炉参数）

五个页面共享顶部「连接参数」卡片：

- **厂商**：11 项预设（DeepSeek / 通义千问 / 混元 / 火山方舟 / 智谱 / Kimi / 文心 / MiniMax / StepFun / MiMo / 自定义），数据源为 `src/promptforge/config/providers.json`。
- **API Key**：密码框，点「显示」可核对。
- **Base URL**：须以 `http://` 或 `https://` 开头，最终请求地址为 `Base URL + /chat/completions`。
- **模型**：模型名。
- **增强风格**：均衡 / 更口语 / 更技术 / 更简洁。
- **目标角色**：用户提示词（默认，输入=给助手看的提示词）/ 系统提示词（输入=一段系统提示词草稿，按角色/边界/输出格式标准重写）。增强与批量增强均按此模式执行，历史档案记录所用模式。
- **温度**：可选 0.3 / 0.5 / 0.7 / 0.9 / 1.0。
- **最大长度**：可选 512 / 1024 / 2048 / 4096。
- 点「保存配置」写入独立工作区；若服务端注入了 `PROMPTFORGE_API_KEY`，Key 输入框置灰。

### 3.1 页面 01 · 单条提示增强

- **输入区**：左栏「IN 原始提示」（带字数计数器），右栏「OUT 增强结果」（只读，带字数计数器）。
- **主动作**：「增强提示词」（`Ctrl+↵`）、双版对比、复制结果、还原输入、清空输入；增强成功后额外出现「存为版本」。
- **提示词体检**：输入框下方常驻「体检」条——左侧大号体检分（0-100），右侧按维度分组的问题 chip。输入停止约 400ms 后自动触发，纯本地规则、零模型调用。
- **场景预设**：代码助手 / 写作润色 / 专业翻译 / SQL 生成 / 代码评审。
- **最近复用**：展示最近 5 条增强过的提示词，一键回填。
- **常见问题折叠区**：内置失败诊断树（鉴权 400 / 限流 429 / 空结果 / 超时 504 / 低质量）。

### 3.2 页面 02 · 批量提示增强

- 多行输入框，**每行一条提示词，空行自动跳过，单次上限 200 条**；单条上限 100,000 字符。
- 按钮：批量增强、导出 CSV、清空输入。
- **超过 20 条时弹出确认框**，说明每条独立调用模型、耗时随条数增长。
- 产出清单：逐条输出原始 → 增强，失败条显示失败原因。

### 3.3 页面 03 · 打磨档案

- 顶部工具行：刷新、导出格式下拉（CSV / Markdown）、导出全部、清空档案、仅看收藏、状态下拉、检索框（`Ctrl+K` 聚焦）。
- 统计条：总计 / 今日 / 成功率 / 平均耗时 / 累计 token / 低质量数。
- 每条记录：星标收藏 + 元信息行 + 摘要预览；操作按钮：复制、载入、版本链、评估。
- **清空档案**：二次确认 → 先原子备份整库（VACUUM INTO + sha256）→ 仅清增强历史（连接配置保留）→ 写审计日志。
- **用量账本**卡：本人按模型 / 按日（近 30 天）汇总；成本需管理员配置单价后才有值。

### 3.4 页面 04 · 五槽指令铸造

分三步：

1. **入炉设计文档**：上传 `.md` / `.txt` 文件，或直接粘贴（文档上限 2,000,000 字符），点「解析并列出目录」。
2. **勾选本期切片**：目录列表勾选章节，选中父章节时其子节自动纳入。
3. **补齐五槽并生成**：任务、本期、代码范围、我的决策；点「生成五槽指令」。

产物区：指令产物（纯本地编译，不消耗 token）、歧义停工警告框、装配报告（文档行数 / token 对比 / 节省率）、模板变量（`{{变量名}}` 动态渲染，变量值 localStorage 持久化自动回填）。

### 3.5 页面 05 · 工坊管理台（仅管理员）

- **平台概览**：账号总数 / 增强记录 / 今日记录 / 累计 Token / 失败与低质量。
- **新成员默认参数**卡：配置厂商 / API Key / Base URL / 模型 / 风格 / 温度 / 最大长度。
- **全员用量账本**卡：跨用户聚合；单价 JSON 输入（元/百万 tokens）。
- **账号管理**卡：新建用户、刷新、过滤、允许自助注册开关；表格列含操作（重置密码、停用/启用、改角色、解锁、代管、导出、删除）。
- **代管面板**：连接配置（API Key 只显示「已设置」掩码）与最近增强记录（管理员对版本链 / diff 只读）。

## 四、新功能操作说明

### 4.1 体检维度分组怎么读

`POST /api/lint` 返回 `{issues, score, dimensions}`。每条 issue 带 `dimension` 字段，返回值含 `dimensions` 九维汇总。

**九维及前端标签**：

| 维度 key | 前端标签 | 缩写 | 主要覆盖的规则 |
|---|---|---|---|
| `security` | 安全风险 | X | 提示词注入、五类明文密钥形态、PII |
| `role` | 角色 | R | 未设定角色、缺「角色」结构槽 |
| `format` | 输出格式 | F | 未说明输出格式、缺「输出格式」结构槽 |
| `constraint` | 约束 | K | 缺「规则/约束」与「流程/步骤」结构槽 |
| `context` | 上下文 | C | 未替换模板变量、缺「目标/验收」与「技能/能力」结构槽 |
| `clarity` | 清晰度 | L | 模糊措辞、空输入、未知 code 兜底 |
| `specificity` | 具体性 | S | 维度位（当前由模糊措辞等规则间接覆盖） |
| `example` | 示例 | E | 示例缺失 |
| `length` | 长度 | N | 过短 / 过长 / 超上限 |

- **体检分**是全局参考分：100 分起扣，`error` 扣 40、`warn` 扣 15、`info` 扣 5，不低于 0。仅供参考，不用于门禁。
- **结构化槽位检测（LangGPT 六段）**：Role / Goal / Output / Rules / Workflow / Skills 六段逐一检测，缺段提示最多 3 条。
- **安全规则组**：提示词注入（`error`）、五类明文密钥形态（`sk-` / `AKIA` / `ghp_` / PEM / JWT，`error`）、PII（`warn`）。
- 体检是建议，误报不致命，可选择忽略，绝不会阻止增强。

### 4.2 双版对比判定怎么用

入口：01 页「双版对比」按钮。

- 选 A 版风格与 B 版风格（默认 A = 均衡，B = 更技术），点「生成两版」。两次调用都照常落库；两侧风格按各自所选生效（v0.1.1 修复：此前风格选择未传达到服务端，两版实际同风格）。
- **配对判定条（`verdict`）**：

  | verdict | 含义 | 触发条件 |
  |---|---|---|
  | `a_wins` | A 版占优 | 指标分差 ≥ 6 且 A 更高 |
  | `b_wins` | B 版占优 | 指标分差 ≥ 6 且 B 更高 |
  | `insufficient` | **证据不足，无法自动判定** | 两版指标分相差小于 6 分 |

- 判定条同时展示四项对比：结构槽位 : 量化信息 : 篇幅 : 指标分（A : B）。
- 指标接近时明确输出「证据不足」，请直接阅读两侧结果，点「采用 A 版」或「采用 B 版」。

### 4.3 缓存命中意味着什么

- **键怎么算**：`make_key = sha256(model + messages + 规范化 params)`。无关键（stream/stream_options/user/metadata）不参与哈希。
- `ttl_seconds = 0` 表示永不过期；`prune(max_entries=2000, max_age_days=30)` 防无限增长。
- **单条输入超过 100,000 字符不缓存**；**缓存绝不存储 API Key**。
- **关闭**：设 `PROMPTFORGE_CACHE=0`，既不读也不写。
- **命中时**：响应体带 `cached=true`；界面上「缓存命中」出现在双版对比弹窗的版本元信息行。

### 4.4 版本链与回滚

入口：03 页某条记录的「版本链」按钮。

- **固化为新版本**：文本框预填当前结果（可编辑）+ 版本说明（必填，≤80 字）+ 来源下拉 + 模型名。
- 版本行**不可变**：任何修改都是插入新行（`version_no = MAX+1`）。
- **回滚**：指针切到目标版本，不产生新行，写 `rollback` 审计。
- **版本对比**：双栏并排 diff（difflib），改动行带字符级行内高亮（仅 ≤2000 字符行）；槽值段逐槽统计；可「复制 Markdown」。
- **评估分数趋势**：≥2 个带评分版本后绘制 SVG 三线趋势图（准确性 / 完整性 / 清晰度）。
- **版本链自愈**：`repair_consistency()` 启动时幂等收敛指针，带 rollback 审计的指针刻意豁免。

## 六、桌面版与命令行用法

Web 版与桌面版**复用完全相同的核心层**，桌面版适合无浏览器环境与服务器/CI 场景。

```bash
# 桌面 GUI
python -m promptforge

# 命令行增强模式
python -m promptforge cli --help
python -m promptforge cli --text "帮我写一个登录页"
python -m promptforge cli --file prompts.txt --out result.csv
python -m promptforge cli --text "..." --style 更技术 --model deepseek-chat
python -m promptforge cli --text "You are a helpful bot" --mode system

# 数据库/版本链/检索索引自检（借鉴 doctor 惯例；只读检查，--fix 才修复）
python -m promptforge cli doctor
python -m promptforge cli doctor --fix

# 五槽指令构造器 CLI（纯本地，零 token）
python -m forge --help
python -m forge --file <设计文档.md> --outline
python -m forge --file <设计文档.md> --pick 3,6.6 --period 一期 \
    --code src/auth.py --task "实现用户登录接口" --decision "采用 JWT 方案"
python -m forge --file <设计文档.md> --pick 3 --out instruction.txt --no-gate
```

**`python -m promptforge cli` 参数**：`doctor`（自检子命令，配 `--fix` 执行修复）、`--text`（单条）、`--file`（批量输入文件）、`--out`（CSV 输出路径）、`--provider` / `--base-url` / `--model` / `--temperature` / `--max-tokens`（覆盖已存配置）、`--mode`（user=普通提示词，默认；system=系统提示词草稿）、`--style`（均衡/更口语/更技术/更简洁，默认均衡）。

**Web API 覆盖参数**（与 CLI 同语义，均可选、缺省不动已保存配置）：`/api/enhance` 与 `/api/batch` 请求体支持 `style`（双版对比按各自风格生效）、`mode`（user/system）、`provider`（仅接受 providers.json 既有预设，Base URL/模型取自服务端预设，不接受任意地址）。

**`python -m forge` 参数**：`--file`（`-` 表示 stdin）、`--text`、`--outline`、`--pick`（章节编号，逗号分隔）、`--task`、`--code`、`--decision`（可重复）、`--period`、`--out`、`--no-gate`（不附加【本期出口】门禁）。

## 七、常见问题与故障排查

### 7.1 增强失败错误码对照表

v0.1.0 起错误响应统一为 `{error, code, hint}`。

| 前端提示 / HTTP | `code` | 含义与处理 |
|---|---|---|
| 400「请先填写 API Key」「Base URL 须以 http:// 或 https:// 开头」等 | `MODEL_NOT_CONFIGURED` | 连接配置缺失或非法：到「连接参数」补齐并保存 |
| 400「鉴权失败（HTTP 401/403），请检查 API Key」 | `AUTH_FAILED` | 模型侧 Key 无效，与本站登录态无关；检查 Key 是否误粘引号 |
| 429「触发限流（HTTP 429）」 | `RATE_LIMITED` | 厂商侧流量保护：等 1 分钟或换模型/账号 |
| 504「请求超时」 | `TIMEOUT` | 上游响应超时（单次默认 90 秒）：稍后重试 |
| 502「模型响应不是有效 JSON（HTTP 200）」 | `BAD_RESPONSE` | Base URL 未指向 OpenAI 兼容的 `/chat/completions` 端点 |
| 502「模型返回为空，将自动重试」 | `EMPTY_RESULT` | 已自动重试 2 次仍为空：换模型或检查 Base URL |
| 502「HTTP xxx: …」 | `UPSTREAM_ERROR` | 上游其它错误：稍后重试或检查 Base URL |

### 7.2 登录与账号类

| 现象 | 原因与处理 |
|---|---|
| 「用户名或密码错误」 | 密码错误，**或**管理员平台口令错误（两者文案刻意一致，防账号枚举） |
| 「尝试过于频繁，请 10 分钟后再试」 | 同一 IP 登录失败达 20 次 / 10 分钟被限流（内存态，重启清零） |
| 账号被锁定 | 连续失败 5 次锁定 15 分钟（DB 持久化）；联系管理员「解锁」 |
| 「您仍在使用初始密码，请先修改密码」 | 管理员建号/重置下发的临时口令未改：按强制改密横幅设置新密码 |
| 「管理员已关闭自助注册」 | 管理员关闭了注册开关 |
| 「注册过于频繁」 | 同一 IP 每小时注册达 5 次 |

### 7.3 结果质量与统计类

| 现象 | 原因与处理 |
|---|---|
| 结果标注「（质量偏低：疑似复述原文）」 | 输出与输入完全相同，或双方均 ≥10 字且相似度 > 0.9。把输入写得更具体再试 |
| 状态栏「结果 N 字，超过 800 字建议精简」 | 超过 800 字软上限：仅告警，不强制截断 |
| 用量卡无变化 / 成本显示 — | 模型响应缺失 `usage` 时按 0 记；成本需管理员配置单价后新增调用才折算 |
| 缓存不生效 | 检查 `PROMPTFORGE_CACHE` 是否被设为关闭值；换模型/风格/温度/最大长度都会改变缓存键 |
| 历史检索搜不到 | 检索匹配输入/输出子串；环境不支持 FTS5 时自动退化为 LIKE |

### 7.4 部署与运维类

| 现象 | 原因与处理 |
|---|---|
| 访问 6085 无响应 | 确认 `docker compose ps` 容器在跑；`docker compose logs -f promptforge` 看日志 |
| 首次登录不知道口令 | `WEB_ADMIN_PASSWORD` 见 `.env` 或启动日志；管理员另需 `WEB_ACCESS_PASSWORD` |
| 清空历史后想找回 | 清空前已自动原子备份整库，备份文件名在状态栏可见 |

## 八、已知限制与设计取舍

- **前端 CSP 需 `'unsafe-inline'`**：前端为内联脚本/样式单页，`script-src`/`style-src` 必须放开 `unsafe-inline`。
- **SSRF 属设计取舍**：增强请求的 Base URL 由各用户自填，内网自建端点为主用例；**请勿将本服务无保护暴露到不受信网络**。
- **登录 IP 限流为内存态**：重启清零（内网单机规模够用）。
- **A/B 判定为静态指标参考**：非统计显著性检验，指标接近时输出「证据不足」而非硬给赢家。
- **单条增强状态栏不显示缓存标记**：`cached=true` 目前仅在双版对比弹窗体现。
- **成本统计需配置单价**：未配置模型单价时成本列显示 —，且只对配置后新增的调用生效。
- **批量增强无服务端取消**：≤200 条 × 90s 同步占用线程，前端有 >20 条确认框。
