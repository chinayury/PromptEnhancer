### 2.2 不修项汇总（SKIP / DOC 理由）

1. **批量增强无服务端取消**：waitress 同步模型下实现可取消需引后台任务表+轮询，改动面大；以确认弹窗 + 文档说明缓解。

3. **`/api/config` 回显本人 API Key**：与桌面版行为一致（本人自见），管理端已掩码。
4. **SSRF（用户自填 base_url）**：产品核心能力包含自建/内网端点，封禁破坏主用例；以部署指引缓解。
5. **CSV 公式注入**：自用导出场景，风险极低；文档提示勿直接交 Excel 执行。
6. **CSP 需 `unsafe-inline`**：内联脚本/样式单页的固有取舍，已记录。

## 三、BUG 修复记录

### 3.1 第一轮（2026-10-12 正式化基线）

#### B-01 用量统计遇脏 usage 值导致已成功的增强返回 500 【高】

- **现象**：模型响应的 `usage` 字段返回非数字字符串时，增强本身已成功、历史已落库，但 HTTP 响应却是 500。
- **根因**：`webapp._record` 将原始 token 值直接传给 `usage.record_usage`，后者 `int()` 对非数字字符串抛 `ValueError`；外层只捕获 `sqlite3.Error`，异常穿透到 Flask 兜底。
- **修复**：新增 `_safe_int()`；`usage.py` 新增 `_to_int()`（脏值折 0）；`record_usage` 外层兜底捕获所有异常（告警不抛）。

#### B-02 模型鉴权失败（AuthError）误报 502 【中】

- **现象**：API Key 填错时前端提示「请求失败（HTTP 502）」，语义为服务器内部错误，误导排查方向。
- **根因**：`_enhance_status_code` 未对 `AuthError` 单独分类，落入兜底 502。刻意**不**映射 401——前端对 401 一律跳登录页，会把「模型 Key 错」误判为「本站登录失效」。
- **修复**：`AuthError → 400`（客户端配置问题语义），错误文案不变。

#### B-03 指令构造控制器无界增长（内存缓涨）【中】

- **现象**：`_forge_ctrls` 按用户缓存控制器，仅在登出/删号时清理；长期运行内存只增不减。
- **根因**：字典缓存无上限、无淘汰。
- **修复**：上限 200 条，超出按插入序淘汰最旧。

#### B-04 构造器文档名无长度上限 【低】

- **现象**：`/api/forge/parse` 的 `name` 参数可传任意长度字符串。
- **修复**：截断至 200 字符。

#### B-05 用户名→工作区路径缺少纵深防御 【高（安全类 BUG）】

- **现象（防御缺口，非可利用漏洞）**：`workspace_dir(username)` 直接拼接路径。现有三层防线下不可达，但若 `pf_users` 表被绕过应用直接篡改注入 `../x` 类用户名，遍历路径会拼出越界目录。
- **修复**：`workspace_dir` 内按建号同款正则二次校验（非法抛 `ValueError`）；`global_stats`/`workspace_stats` 对非法名计 broken/零值，聚合不中断。

#### B-06 大批量提交无规模确认（体验缺陷）【低】

- **现象**：一次提交上百条时界面长时间无反馈，易被误判为卡死。
- **修复**：前端在 >20 条时弹确认框，明示耗时口径。服务端 200 条上限不变。

### 3.2 第二轮（2026-10-28）

#### B-05（续）上游 200 但响应非 JSON → 未处理异常 500

- **现象**：上游网关/反代返回 HTTP 200 但正文是 HTML 错误页时，增强请求返回 500。
- **根因**：`engine._http_post` 把 `json.loads` 放在传输异常捕获块内，`JSONDecodeError` 直接穿透。
- **修复**：解码与解析移出传输异常捕获块，失败统一抛 `EnhanceError`，走既有失败提示链路。

#### B-06（续）畸形 choices/usage 结构 → AttributeError 500

- **现象**：模型响应 `choices:[null]` 或 `usage:"bad"` 之类畸形结构时 500。
- **根因**：`_do_one_request` 对非 dict 元素直接 `.get` 崩溃。
- **修复**：抽取 `_chat_request`，对 body/choices[0]/message/usage 逐层 isinstance 校验，结构异常按空内容处理。

#### B-07 workspace_stats 对缺失库产生空库文件

- **现象**：管理员账号列表页偶发在 `data/users/<名>/` 下出现 0 字节 promptforge.db。
- **根因**：`users.workspace_stats` 直接 `sqlite3.connect(path)`——SQLite 对不存在路径默认创建空文件。
- **修复**：先 `os.path.exists(dbp)` 再连接，缺失按 0 条计。

#### B-08 增强输入无长度上限

- **现象/风险**：单条或批量输入长度不受限，超长文本会全量发往模型并原文入库。
- **修复**：新增 `MAX_INPUT_CHARS = 100_000`，超限直接 400（不发起模型调用）。

### 3.3 第三轮（2026-11-08）

#### C-01 `promptforge/core/__init__` 重导出 `lint` 函数遮蔽子模块名

- **现象**：新增 `lint.py` 后 `from promptforge.core import lint` 拿到的是函数而非模块，调用 `lint.lint(text)` 报 `AttributeError`。
- **根因**：模块名与 `from X import lint` 的绑定冲突。
- **修复**：`__init__.py` 不再重导出 `lint` 函数，调用方统一 `from promptforge.core import lint`（模块）→ `lint.lint()`。
- **验证**：此缺陷在联调测试阶段被 8 条失败用例立即暴露，是测试门禁生效的典型案例。

### 3.4 第四轮（2026-11-10 正式化）

#### D-01 LLM 响应缓存首次启动静默失效 【高】

- **现象**：Web 版首次启动后，第一次增强调用完全不命中缓存，缓存写入也静默失败；界面无报错，该状态持续到库被手工清理。
- **根因**：建表被放在**模块导入期**执行一次。导入期目录不存在 → 建表失败；`ensure_schema()` 不会在每次操作前重试，「表从未建成」被永久遗留，后续每次 `get/put` 都失败，异常被 engine 兜底吞掉——整条缓存链路**静默失效**。
- **修复**：删除导入期建表调用，模块导入期零副作用；所有公开操作统一走 `_cursor()` 上下文，进入即执行幂等 DDL，schema 由首次使用时自然建立。

#### D-02 登录失败计数竞态（并发覆盖）【高】

- **现象**：两个并发登录失败请求同时处理时，失败计数可能互相覆盖，导致第 5 次失败没有触发锁定。
- **根因**：`users._bump_fail` 原为「读-改-写」两段式，两个并行请求基于同一旧值计算，后者覆盖前者。
- **修复**：改为单条原子 UPDATE（CASE 以旧行值为基准），语义不变（第 5 次失败即锁 15 分钟）。

#### D-03 登录计时侧信道（账号枚举）【中】

- **现象**：用不存在的用户名登录比用存在的用户名登录返回明显更快，响应时间差可被用来枚举「账号是否存在」。
- **根因**：`users.authenticate` 在 `row is None` 分支直接 `raise`，未执行任何口令校验成本。
- **修复**：新增 `_equalize_timing()`——导入期一次性计算哑哈希，用户不存在时也执行一次同等成本的 PBKDF2，封堵计时侧信道；文案仍统一。

#### D-04 `_page_raw` 使用未导入的 `abort`（潜在 NameError）【中】

- **现象**：请求 `web/` 下不存在的静态资源时，本应返回干净 404，实际因 `abort` 未导入抛 `NameError`，被兜底转成 500。
- **根因**：`webapp.py` 新增 `_page_raw()` 时引用了 `abort`，但顶部 flask 导入行漏补。
- **修复**：flask 导入行补入 `abort`，分支恢复 404 语义。

#### D-05 favicon 404（站点图标缺失）【低】

- **现象**：两个页面均未声明图标，浏览器默认请求 `/favicon.ico` 恒 404，标签页无品牌标识。
- **修复**：新增 `web/favicon.svg` + 两页面 `<link rel="icon">` + 公开路由 `GET /favicon.svg`（24h 缓存头）。

#### D-06 CHANGELOG 条目排序不符合本文件约定 【低】

- **现象**：`CHANGELOG.md` 的第四轮条目被插入到一级标题与说明行之上，文档标题不在文件首行。
- **修复**：将第四轮条目整体移至标题与说明行之下、第三轮条目之上。

### 3.5 第五轮（2026-11-14）

#### D-07 A/B 双版对比风格选择失效 【高】

- **现象**：前端「双版对比」每次调用都传了 `style`（A 版/B 版各自所选风格），但服务端
  `/api/enhance` 只读已保存配置、从不读取请求体里的 `style`——两版实际始终同风格，
  配对判定退化为同口径对比（回归发现于第五轮维护巡检）。
- **修复**：新增 `_apply_request_overrides()` 统一合并「请求覆盖 > 已保存配置」，
  `/api/enhance` 与 `/api/batch` 共用；覆盖面收敛为 `style` / `mode` / `provider`
  三个白名单字段，缺省一律不动（历史行为逐字节兼容）。

### 4.2 第二轮（2026-10-28）：F2 提示词版本链与 diff + 评估裁判

- **版本链（主项）**：`prompt_versions` 表（UNIQUE(record_id, version_no) 防并发撞号、parent_id 成链、source 标记 init/manual/enhance、score 评估列）+ `version_audit` 审计表 + `current_version_id` 指针列。版本行不可变，任何修改=插新行。存量库由 `ensure_version_schema()` 惰性补列补表。
- **版本接口**：`POST/GET /api/history/<rid>/versions`、`POST .../activate`（指针式回滚）、`GET .../diff`（结构化并排行对 + 槽值统计 + unified 文本）；管理员只读可见。
- **diff 算法**（stdlib difflib，零新依赖）：`ndiff` 解析为并排行对、`SequenceMatcher.get_opcodes` 行内高亮、`unified_diff` 统一格式、槽值 `json.dumps(sort_keys=True)` 规范化后逐槽统计。
- **评估裁判**：`POST /api/history/<rid>/evaluate` 复用已配置模型打分（准确性/完整性/清晰度 1-10 + 建议），评分入版本元数据；失败降级为明确错误提示。引擎新增 `raw_completion()`。
- **前端**：历史页版本链/评估入口、版本链面板（固化/列表/回滚/双栏 diff）、单条增强「存为版本」。

## 六、已知限制与后续规划

### 6.1 已知限制（登记在案，不阻塞使用）

- 批量增强无服务端取消（≤200 条 × 90s 同步占用线程，前端有 >20 条确认框）。
- 登录/注册限流为内存态，重启清零。
- `.web_secret` 文件权限依赖宿主 OS（Windows chmod 无效）。
- CSV 导出公式注入（自用场景，已提示勿直接交 Excel 执行）。
- 缓存无 HTTP 管理端点（stats/clear/prune 仅库级 API），命中率需直连库观测。
- SSRF（用户自填 base_url）为设计取舍（内网自建端点为主用例）。
- CSP 需 `unsafe-inline`（内联脚本/样式单页）。
- A/B 判定为静态指标参考，非统计显著性检验。

### 6.2 后续规划（按优先级）

1. 视觉残留清理（趋势图色值入主题令牌）。
2. 借鉴项 B-10~B-12 落地（lint 规则/场景预设数据外置、diff 粒度开关、FakeLLM 确定性测试）。
3. 缓存运维面（管理台只读统计卡：entries/hits/bytes 与命中率）。
4. A/B 完整统计显著性（McNemar/置换检验，需用户标注期望输出，列为后续）。
5. 批量增强服务端可取消（任务表 + 轮询接口）。
6. 评估结论回灌重写（B-13）、导入面出现后再做备份安全基线（B-14）。
7. 单条历史记录的删除能力。
8. UI 状态（窗口尺寸、上次选中厂商）记忆。
9. 提示词模板外置为文件，支持多语言与热更新（参照 .prompty 的 TOML 头格式，配导入面安全检查清单）。
10. `serve` 子命令（将增强能力以本地 HTTP 服务暴露，供多端调用）。
11. 收藏升级为「可复现资产」（B-15：绑定版本 + 复现输入，历史导出附带）。
12. 跨厂商并行对比前端（B-16：2-4 厂商勾选，复用 A/B 配对判定；API 覆盖已就绪）。
